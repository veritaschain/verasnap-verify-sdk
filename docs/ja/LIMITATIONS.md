# 限界と未対応事項（0.1.0）

## 撮影時証明では原理的に分からないこと

- **現物の偽装。** わざと付けた傷、古い傷の撮り直し、別の車両、印刷物や画面に表示した画像を本物のカメラで撮ったもの。偽りの場面を本物のカメラで撮れば、検証は通ります。損害鑑定、車両の同一性確認（ナンバーや車台番号を写し込む）、既存の不正分析と組み合わせてください。
- **誰が撮ったか。** VeraSnapは端末で生体認証が行われたことと結果を記録しますが、人物は特定しません。組織的な不正では、契約者本人が進んで撮影することも多くあります。
- **修理工場・代理店による不正。** 事業者が自分の登録端末で撮影する場合、証明が示すのは「その事業者がその時に撮った」ことまでで、損害の水増しは防げません。

## このバージョンで検証していないこと

- **証明の中に書かれた端末証明**（`KeyAttestation`、`CaptureAssertion`、Androidのセキュリティレベル）は、アプリ1.6.1と同じく「記載されているが未検証」として表示します。端末を信頼する根拠は、**鍵の登録**だけです。撮影ごとのApp Attestアサーションと Play Integrity の検証は、CPP v1.7 Capture Environment Attestation で予定しています。
- **不正な端末でのカメラ映像の注入。** Androidでは、登録時に検証済みブートとブートローダーのロックを要求します（KeyMintが両方を証明します）。iOSのApp Attestはアプリ本体が正規であることを示しますが、脱獄を確実には検出しません。仮想カメラ・センサー注入の検知（CEA）は未実装です。
- **画面の再撮影。** アプリは複数の手法で画面の再撮影を判定して記録します（社内評価で約96%。第三者の評価はありません）。SDKはこの結果を使っていません。
- **位置情報。** GPSの値は端末の申告で、GNSSの偽装は検知しません。
- **TSAの失効確認。** CRL/OCSPは確認しません（アプリと同じ）。証明書チェーンは、同梱のルートに対してgenTime時点で検証します。
- **チェーン情報**（`chain_context` / `ChainContext`）は署名の対象外です。削除件数は、署名されていない参考値として表示します。
- **撮影時刻**は端末の時計の値です。タイムスタンプが示すのは「genTimeの時点で証明が存在していた」ことだけです。60分ルールにより、警告なしにさかのぼれる時間を制限しています。

## アプリとの違い（いずれも意図的なもの）

| 項目 | アプリ1.6.1 | SDK 0.1.0 |
|---|---|---|
| 既知の署名鍵 | その端末自身の鍵だけ | 保険会社の台帳にある、ハードウェア証明を通して登録された鍵 |
| 内部用 `proof.json` のEventHash | iOS 1.6の検証モデルを通して再計算（未知の項目は捨てられる。`CaptureAssertion` を含むiOSのイベントは不一致になる既知の不具合） | まず書かれたとおりのイベントで計算し、iOSモデルは予備に使う。その場合、署名の対象外の項目があれば警告（`unsigned_fields`） |
| TSAの信頼 | iOSのシステム信頼ストア | 同梱のルート（DigiCert G4、USERTrust、Sectigo R46、Apple Root CA、GlobalSign R45）。差し替え可能 |
| 失効した鍵 | なし | 警告（`signer_key/revoked`） |
| 要約の文言 | 黄の結果でも「写真の完全性を確認」と表示 | 署名者が既知の場合だけ表示 |

## 主張していないこと

- C2PAへの適合（VeritasChainは参加意向の表明のみ）
- 第三者によるセキュリティ監査
- 証明が裁判所・規制当局・保険会社に採用されること
- Merkle構造はアプリと同じ（0x00/0x01のドメイン分離なし）で、draft-vso-cpp-core にはまだ合わせていない
